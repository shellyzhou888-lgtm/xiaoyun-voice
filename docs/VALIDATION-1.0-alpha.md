# 小云 1.0-alpha 验收记录

版本：`1.0.0-alpha.1`。日期：2026-09-11，Windows，Node.js 24，Edge 与 Chrome 独立 headless 浏览器，用户指定 Python 环境。

## 实施结果

- 保留 Qwen 原生实时语音；普通回应作为完整播放单元，后台结果等待实际音频排空后接入。没有独立 TTS，也不依靠字幕句号切断音频。
- Qwen 使用通用交互/路由提示；Pi 按需读取项目 Skill 与参考资料。默认项目不加载销售 Skill，不创建销售数据库。
- Pi 能观察当前页面并调用已注册业务动作；SDK 与后台校验上下文版本，动作共用串行通道，返回真实执行回执。Qwen 同轮多步页面操作统一交给 Pi，并合并同轮已有任务。
- 新增等待期间聊天、Skill 分析与多步操作、通用方案三组大屏用例；保留现有角色、工具栏、拖动、结果卡和持续对话规则。

真实销售流程：读取 Skill 和参考资料、SQL 查询、Python 计算、观察页面及四步操作。最终切换到华东、2026 年、利润指标和经营总览；结论为“2026年华东利润最高，约420.3万元，占四地区总利润34.78%，页面已切换。”。Qwen 自动播完结果摘要。

真实会议流程：Pi 追问会议室，用户补充“松柏厅”后恢复原任务；完成后改为“银杏厅”建立第二个任务。两个任务都使用会议 Skill、业务日程工具和实际浏览器动作；业务日程是固定测试数据，不代表真实会议安排。

独立安装：在全新目录安装统一 `.tgz`，运行 init，启动安装包里的后台及项目模块，再运行独立会议页面。原按钮和语音共用业务函数；Skill 和结果播报正常。最终包样本中，文字操作到页面动作事件为 **902 ms**，这是一次同机样本，包含页面输入操作开销，不是 P95 或实体麦克风延迟。

精简证据：[validation-1.0-alpha.json](evidence/validation-1.0-alpha.json)。在完整开发/展示工作区中，播放回归可复现：`npx tsx scripts/verify-playback.ts msedge`，或末尾换成 chrome。该浏览器夹具脚本位于完整开发工作区；组件库包含可直接运行的 40 项行为检查。浏览器夹具不要求模型 Key，使用临时数据目录与可控响应，浏览器实际消费 PCM。

## 本轮修复的集成问题

- Skill 初始化期间第一条指令可能早于连接 Promise 注册，已让唤醒后的输入统一等待完整初始化，并添加入口竞态测试。
- Qwen 同轮直接执行多步按钮又派给 Pi，会导致重复操作；现已统一转交并复用同轮任务受理。
- 聊天期间不再积压等待提示，过时等待语不会在聊天结束后补播。

## 验证边界

本次真实模型联调使用文字输入，浏览器真实播放生成音频；没有把它写成实体麦克风、扬声器或大厅声学验收。关键词唤醒、触摸操作和现场插话仍需用户实际体验，因此发布为 alpha。

任务取消或结束会话会阻止剩余页面步骤；已开始的宿主业务函数不自动回滚。Skill 修改后需重启后台；超过能力范围、缺少数据或动作失败时应返回实际限制。

发布完成：[私有预发行 v1.0.0-alpha.1](https://github.com/personoj/xiaoyun-voice/releases/tag/v1.0.0-alpha.1)。本机后台及一键启动器已验证使用 1.0.0-alpha.1。

发布后从私有 GitHub 的 v1.0.0-alpha.1 标签直接 npm 安装成功，构建产物、CLI、server 导出与 Skill 资料可用。
