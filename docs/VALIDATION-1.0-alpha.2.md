# 小云 1.0-alpha.2 修复记录

版本：`1.0.0-alpha.2`。日期：2026-09-11，Windows，Node.js 24，用户指定 Python 环境。

## 用户报告与原因

用户通过麦克风要求分析 2026 年各地区利润、找出最高地区及其占比，并切换页面和给出比较表。alpha.1 实际日志显示只受理一个任务，第 4 轮已经算出最高地区及占比；后续页面操作反复被浏览器以版本不一致拒绝，最终达到程序写死的 16 轮执行上限。该上限是本组件的配置失误，不是用户要求，也不是 DeepSeek 的推理 token 限制。

SDK 在握手前排队的旧 actions.update 晚于新页面快照发送，后台又无条件接收旧版本，造成页面版本倒退。等待语阶段约 17 秒的声音也明显偏离预期短句。旧日志没有保存完整播报字幕，无法逐字还原用户听到的复述；源码的“朗读最新用户消息”指令在音频历史中目标不明确。

## 修复

- SDK 等待后台 ready 后再发送控制消息与音频，合并握手期间配置为最新完整快照；旧配置不再覆盖 hello，唤醒先于缓冲音频发送。
- 后台拒绝倒退版本；页面动作回执附带 SDK 当前快照，动作冲突时下一次观察能获得新状态。宿主业务修订号使用 viewRevision，避免与协议版本混淆。
- 每次播报在 Qwen 指令中直接指定唯一文本，明确不复述历史问题或任务标题。继续使用原生实时语音，没有增加 TTS 服务。
- 等待语音缓存仅接收与预定短句一致的播报；日志记录预定文本与实际输出字幕，不记录音频或模型思考。
- 删除默认 16 轮限制。AGENT_MAX_TURNS 默认 0（不限制）；正整数才启用上限，错误明确说明后台配置，任务仍可取消。

## 验证结果

- 完整工作区与独立组件库：类型检查、构建、43 项行为测试通过。新增覆盖初始化快照乱序、拒绝动作后快照恢复、默认超过 16 轮可完成及显式轮数限制。
- 同一句完整需求经合成录音输入 Edge 浏览器麦克风，经过真实 AudioWorklet、Qwen、Pi、SQLite/Python 和实际销售大屏。两次运行分别 5、7 轮成功，均仅创建一个任务，工具无错误。
- 最后一次的比较表包含四个地区、华东利润 4,202,871.10 元、总利润 12,084,214.50 元及华东占比 34.78%。验证页面为华东、2026 年、利润和经营总览。
- 等待播报为“我来处理这个任务。”，长等待补充为“任务还需要一点时间。”，均与指定文本一致；结果播报完成以浏览器实际播放排空回执确认。
- Edge 与 Chrome 的可控协议验证通过：完整聊天播完后交接并行结果、插话与迟到包丢弃、页面版本冲突、等待句交接、重播及阅读保护。该组使用模型夹具与实际 AudioWorklet。
- 本机后台 /api/health 返回 1.0.0-alpha.2，两个模型配置就绪；启动器和实际展示页加载通过，无页面异常。

真实模型复测脚本：完整工作区 `npx tsx scripts/verify-voice-request.ts`，读取已有后台 Key、使用隔离数据库。可控播放回归：`npx tsx scripts/verify-playback.ts msedge` 或 `chrome`。

这不是实体麦克风和扬声器声学验收。alpha.1 的简化页面/文字测试未覆盖此次完整大屏的初始化与语音历史组合，当前已将它纳入复测；仍需用户验证真人发音、回声和听感。
