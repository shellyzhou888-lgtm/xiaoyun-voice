# Local keyword spotting resources

The worker performs inference on the user's computer. It downloads only the
files below from the configured local asset server; microphone audio is not sent
to a speech service for wake-word detection. Chrome and Edge with WebAssembly SIMD
are supported. The runtime is single-threaded and does not require COOP/COEP.

## Runtime

- Engine: [k2-fsa/sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), Apache-2.0.
- Browser build: [fatsunshineboy/sherpa-onnx-wasm-kws](https://github.com/fatsunshineboy/sherpa-onnx-wasm-kws/tree/bd8785e2c55e65ac4d7bbc52eaf7780bb0fb81d7), pinned commit `bd8785e2c55e65ac4d7bbc52eaf7780bb0fb81d7`.
- Files are the unmodified matching JS bindings, Emscripten loader, WASM, and data
  bundle from that commit. The build repository describes its upstream CMake
  settings. It uses the real KeywordSpotter/KeywordStream C API.
- The upstream source commit used by that third-party compiler is not recorded;
  this is a pinned, functionally verified prebuilt distribution, not a claim of
  a locally reproduced compiler build.

## Model

- Official model: [sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20](https://github.com/k2-fsa/sherpa-onnx/releases/download/kws-models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20.tar.bz2).
- The data package contains the full-precision chunk-16/left-64 epoch-13 encoder,
  decoder, joiner and token table. During integration all three embedded model
  byte ranges matched the separately downloaded official model files exactly.
- The package's embedded README still refers to the older WenetSpeech model;
  the actual model payload is the 2025-12-20 Chinese/English 3M model above.
- Input: mono 16 kHz signed PCM16, typically 1600 samples per message.
- Default phrase: `你好小云`, phonemes `n ǐ h ǎo x iǎo y ún`.
- The four runtime/model files total about 23.7 MB. The prebuilt engine reserves
  a 512 MB WASM memory address space; use one detector worker per component.

## Configuration and lifecycle

`keywords.json` maps Chinese phrases to the model's pinyin initial/final tokens.
To add a different Chinese phrase, run `scripts/setup-wake-assets.py --phrase ...`
with the configured Python environment (requires the `pypinyin` distribution),
rebuild the SDK, then pass the same string as `wakeWord` to the component.
The setup script reuses existing resources and downloads only missing ones.
It does not install or upgrade packages. English phrases require an explicit
phoneme lexicon entry and are not generated by this Chinese setup command.

Worker initialization receives `{type:'init',baseUrl,phrase}` and returns
`{type:'ready'}` only after creating the model and stream. It accepts
`{type:'audio',pcm}` and `{type:'reset'}`; detections emit `{type:'wake',keyword}`.
Errors emit `{type:'error',message}`. The SDK terminates the worker on destroy,
which releases its WASM instance, model memory and audio buffers. `reset` reuses
the stream and never allocates an extra stream.

## Functional validation

The pinned runtime initialized and detected eight expected keywords across the
official Chinese speech fixtures. It also detected `你好小云` in a 16 kHz PCM
utterance generated locally using Windows' Microsoft Huihui Desktop voice.
This verifies the inference path and configured phonemes; live microphone
accuracy and hallway false-wake rates still require the user's device tests.
